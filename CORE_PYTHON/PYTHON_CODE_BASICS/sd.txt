# `*args` and `**kwargs` — Detailed Study

This is an important Python function concept. Don't just memorize the syntax—we'll understand **why it exists and what Python is actually doing**.

---

# 1. First: the problem `*args` solves

Normally, when defining a function, you specify how many parameters it accepts:

```python
def add(a, b):
    return a + b
```

You can do:

```python
add(10, 20)
```

But what if you don't know beforehand how many values the user will provide?

Maybe:

```python
add(10, 20, 30)
```

or:

```python
add(10, 20, 30, 40, 50)
```

This won't work with:

```python
def add(a, b):
```

because the function expects exactly two arguments.

That's where **variable-length arguments** come in.

---

# 2. `*args`

`*args` allows a function to accept **any number of positional arguments**.

Example:

```python
def add(*args):
    print(args)
```

Now:

```python
add(10, 20)
```

Output:

```text
(10, 20)
```

And:

```python
add(10, 20, 30, 40, 50)
```

Output:

```text
(10, 20, 30, 40, 50)
```

The important thing:

> `args` becomes a **tuple**.

So:

```python
def add(*args):
```

means:

> "Collect all extra positional arguments into a tuple called `args`."

---

# 3. Why is it called `args`?

`args` isn't a special keyword.

You could technically write:

```python
def add(*numbers):
    print(numbers)
```

This works exactly the same.

Even:

```python
def add(*anything):
    print(anything)
```

works.

But Python convention is:

```python
*args
```

So use `args` because everyone expects it.

---

# 4. Using `*args`

Now let's actually use the values.

```python
def add(*args):
    total = 0

    for num in args:
        total += num

    return total
```

Now:

```python
print(add(10, 20))
```

Output:

```text
30
```

And:

```python
print(add(10, 20, 30, 40))
```

Output:

```text
100
```

And:

```python
print(add())
```

Output:

```text
0
```

Because:

```python
args == ()
```

---

# 5. `*args` is a tuple

This is something you should remember.

```python
def test(*args):
    print(type(args))
```

Calling:

```python
test(1, 2, 3)
```

gives:

```text
<class 'tuple'>
```

Conceptually:

```text
test(1, 2, 3)
       ↓
     *args
       ↓
   (1, 2, 3)
```

So you can use tuple operations:

```python
def test(*args):
    print(len(args))
    print(args[0])
    print(args[-1])
```

---

# 6. `*args` doesn't mean "multiple arguments" by itself

This distinction is important.

Consider:

```python
def test(*args):
    ...
```

The `*` tells Python:

> Collect positional arguments.

The name `args` is just a variable name.

You could write:

```python
def test(*numbers):
    ...
```

Python doesn't care about the name.

---

# 7. Normal parameters + `*args`

You can combine normal parameters with `*args`.

```python
def greet(name, *messages):
    print("Name:", name)
    print("Messages:", messages)
```

Call:

```python
greet("Adarsh", "Hello", "How are you?", "Good morning")
```

Then:

```text
name
 ↓
"Adarsh"

messages
 ↓
("Hello", "How are you?", "Good morning")
```

So:

```python
def greet(name, *messages):
```

means:

* first positional argument → `name`
* remaining positional arguments → `messages`

---

# 8. A very important example

```python
def student(name, age, *subjects):
    print(name)
    print(age)
    print(subjects)
```

Call:

```python
student(
    "Adarsh",
    22,
    "Python",
    "Machine Learning",
    "DSA"
)
```

Output:

```text
Adarsh
22
('Python', 'Machine Learning', 'DSA')
```

Here:

```text
name = "Adarsh"
age = 22
subjects = ("Python", "Machine Learning", "DSA")
```

---

# 9. Now the second concept: `**kwargs`

Suppose we have:

```python
def student(name, age):
    ...
```

We can call:

```python
student(name="Adarsh", age=22)
```

But what if we want to accept an unknown number of **keyword arguments**?

For example:

```python
student(
    name="Adarsh",
    age=22,
    city="Meerut",
    branch="CSE",
    college="XYZ"
)
```

We don't necessarily want to define:

```python
def student(name, age, city, branch, college):
```

That's where `**kwargs` comes in.

---

# 10. What is `**kwargs`?

`**kwargs` allows a function to accept an arbitrary number of **keyword arguments**.

Example:

```python
def student(**kwargs):
    print(kwargs)
```

Call:

```python
student(
    name="Adarsh",
    age=22,
    branch="CSE"
)
```

Output:

```python
{
    'name': 'Adarsh',
    'age': 22,
    'branch': 'CSE'
}
```

The important thing:

> `kwargs` becomes a **dictionary**.

---

# 11. `kwargs` is a dictionary

```python
def student(**kwargs):
    print(type(kwargs))
```

Calling:

```python
student(name="Adarsh", age=22)
```

gives:

```text
<class 'dict'>
```

Conceptually:

```text
student(name="Adarsh", age=22)
              ↓
           **kwargs
              ↓
{
    "name": "Adarsh",
    "age": 22
}
```

So remember:

```text
*args   → tuple
**kwargs → dictionary
```

This is one of the most important facts.

---

# 12. Accessing `kwargs`

Since it's a dictionary:

```python
def student(**kwargs):
    print(kwargs["name"])
    print(kwargs["age"])
```

Call:

```python
student(name="Adarsh", age=22)
```

Output:

```text
Adarsh
22
```

You can also loop:

```python
def student(**kwargs):
    for key, value in kwargs.items():
        print(key, ":", value)
```

Calling:

```python
student(
    name="Adarsh",
    age=22,
    branch="CSE"
)
```

Output:

```text
name : Adarsh
age : 22
branch : CSE
```

---

# 13. Why `kwargs`?

Again, `kwargs` is just a convention.

This works:

```python
def student(**data):
    print(data)
```

But normally write:

```python
def student(**kwargs):
```

because that's the standard Python convention.

---

# 14. `*args` vs `**kwargs`

This is the core distinction.

|           | `*args`              | `**kwargs`        |
| --------- | -------------------- | ----------------- |
| Accepts   | Positional arguments | Keyword arguments |
| Stores as | Tuple                | Dictionary        |
| Example   | `f(10, 20)`          | `f(a=10, b=20)`   |
| Syntax    | `*args`              | `**kwargs`        |

Think:

```text
*     → positional
**    → keyword
```

---

# 15. Example showing both

```python
def test(*args, **kwargs):
    print("args:", args)
    print("kwargs:", kwargs)
```

Call:

```python
test(
    10,
    20,
    30,
    name="Adarsh",
    age=22
)
```

Output:

```text
args: (10, 20, 30)

kwargs: {
    'name': 'Adarsh',
    'age': 22
}
```

So Python separates them:

```text
10, 20, 30
     ↓
   args

name="Adarsh", age=22
     ↓
   kwargs
```

---

# 16. Function with everything

You can have:

```python
def function(a, b, *args, **kwargs):
    ...
```

Example:

```python
def example(a, b, *args, **kwargs):
    print("a:", a)
    print("b:", b)
    print("args:", args)
    print("kwargs:", kwargs)
```

Call:

```python
example(
    1,
    2,
    3,
    4,
    5,
    name="Adarsh",
    age=22
)
```

Result:

```text
a: 1
b: 2

args: (3, 4, 5)

kwargs: {'name': 'Adarsh', 'age': 22}
```

The flow is:

```text
1 → a
2 → b
3,4,5 → args
name, age → kwargs
```

---

# 17. Now the REALLY important part: unpacking

So far we've seen:

```python
*args
```

collect arguments.

But `*` can also do the **opposite**.

It can **unpack** a collection.

---

# 18. Unpacking with `*`

Suppose:

```python
numbers = [10, 20, 30]
```

And:

```python
def add(a, b, c):
    return a + b + c
```

Normally:

```python
add(10, 20, 30)
```

But we have a list.

We can unpack it:

```python
add(*numbers)
```

Python effectively turns:

```python
add(*numbers)
```

into:

```python
add(10, 20, 30)
```

So:

```text
numbers
[10,20,30]
    ↓ *
10,20,30
    ↓
add(10,20,30)
```

---

# 19. `*` isn't only for function definitions

This is a common misconception.

`*` has multiple uses.

### Collecting:

```python
def test(*args):
```

### Unpacking:

```python
test(*numbers)
```

Same symbol, opposite direction.

---

# 20. Unpacking a dictionary with `**`

Suppose:

```python
data = {
    "name": "Adarsh",
    "age": 22
}
```

And:

```python
def student(name, age):
    print(name, age)
```

Instead of:

```python
student(
    name="Adarsh",
    age=22
)
```

you can do:

```python
student(**data)
```

Python effectively does:

```python
student(
    name="Adarsh",
    age=22
)
```

So:

```text
dictionary
    ↓ **
keyword arguments
    ↓
function
```

---

# 21. `*` vs `**` unpacking

Remember:

```python
*list_or_tuple
```

unpacks into **positional arguments**.

```python
**dictionary
```

unpacks into **keyword arguments**.

Example:

```python
numbers = [10, 20]

def add(a, b):
    return a + b

add(*numbers)
```

And:

```python
data = {
    "a": 10,
    "b": 20
}

add(**data)
```

Both work.

---

# 22. Why do we actually need this?

This is where `*args` and `**kwargs` become useful in real Python.

Suppose you're creating a function that forwards arguments to another function.

```python
def calculate(a, b):
    return a + b
```

You might create:

```python
def wrapper(*args, **kwargs):
    return calculate(*args, **kwargs)
```

Now `wrapper()` can accept flexible arguments and pass them along.

This pattern appears **everywhere in Python libraries**.

You'll encounter it much more when you reach:

* OOP
* decorators
* NumPy
* Pandas
* PyTorch
* scikit-learn
* APIs/frameworks

---

# 23. Example related to ML

Imagine a model function:

```python
def train_model(X, y, **kwargs):
    print("Training...")
    print(kwargs)
```

You could call:

```python
train_model(
    X,
    y,
    epochs=100,
    learning_rate=0.01,
    batch_size=32
)
```

Then:

```python
kwargs
```

contains:

```python
{
    "epochs": 100,
    "learning_rate": 0.01,
    "batch_size": 32
}
```

This is why you'll see flexible keyword arguments frequently in ML libraries.

---

# 24. Important mistake: `*args` doesn't accept keyword arguments

This:

```python
def test(*args):
    print(args)
```

Calling:

```python
test(a=10)
```

doesn't put `a=10` inside `args`.

That's a keyword argument.

You need:

```python
def test(**kwargs):
```

So:

```text
test(10)
      ↓
    args

test(a=10)
       ↓
    kwargs
```

---

# 25. Important mistake: `**kwargs` doesn't accept ordinary positional values

This:

```python
def test(**kwargs):
    print(kwargs)
```

Then:

```python
test(10, 20)
```

is invalid.

Because `kwargs` expects:

```python
key=value
```

like:

```python
test(a=10, b=20)
```

---

# 26. Ordering rules

When combining parameters, the usual structure is:

```python
def function(
    normal_parameters,
    *args,
    keyword_parameters,
    **kwargs
):
```

For example:

```python
def example(a, b, *args, c=10, **kwargs):
    ...
```

You don't need to memorize every advanced ordering rule right now, but you **should understand** that Python has rules about where positional parameters, `*args`, keyword-only parameters, and `**kwargs` can appear.

---

# 27. A very useful example

```python
def student(name, *subjects, **details):
    print("Name:", name)

    print("Subjects:")
    for subject in subjects:
        print("-", subject)

    print("Details:")
    for key, value in details.items():
        print(key, ":", value)
```

Call:

```python
student(
    "Adarsh",
    "Python",
    "DSA",
    "ML",
    age=22,
    branch="CSE"
)
```

Conceptually:

```text
name
↓
"Adarsh"

subjects
↓
("Python", "DSA", "ML")

details
↓
{
    "age": 22,
    "branch": "CSE"
}
```

This is a very good example to understand the whole concept.

# 28. The mental model you should remember

Think of a function like a machine.

### `*args`

```text
10  20  30  40
 \   |   |   /
      ↓
    *args
      ↓
(10,20,30,40)
```

### `**kwargs`

```text
name="Adarsh"
age=22
branch="CSE"
       ↓
    **kwargs
       ↓
{
 name: "Adarsh",
 age: 22,
 branch: "CSE"
}
```

### Unpacking

Opposite direction:

```text
(10,20,30)
     ↓ *
10  20  30
```

and:

```text
{
 "a":10,
 "b":20
}
     ↓ **
a=10, b=20
```
